# Internationalization

> **Maintenance Invariant:** Where user-facing text lives, how a language is chosen, how text reaches each surface, what stays English. Update in the SAME commit as any locale, key or mechanism change. Token-optimized: imperative, no prose, no redundancy.
> **Answers:** Where does UI text live? Which language does a reader get? How does text reach the popup, the page and the stylesheet? What stays English, and why? How do I add a language?

## Catalog

`public/_locales/<locale>/messages.json`, Chrome's `i18n` format. Same files on Firefox. No dependency, no permission.

`default_locale: 'en'` in `wxt.config.ts`. Shipped: `en` (source), `es`, `de`, `fr`, `pt_BR`, `ja`, `zh_CN`, `zh_TW`.

**`en` is the source.** `MessageKey` in `core/messages.ts` is its key set, so a mistyped key fails the typecheck. Every other locale carries exactly those keys.

## Which language a reader gets

The browser chooses: its UI language, then the base language (`es-MX` -> `es`), then `en`. No setting inside FeedLens.

- Only `pt_BR` ships, so other Portuguese readers get English.
- **A missing key returns an empty string in both browsers**, never an error. The popup would render blank. `src/locales.test.ts` is the only guard.

## How text reaches each surface

| Surface                                 | How                                                                                                        |
| :-------------------------------------- | :--------------------------------------------------------------------------------------------------------- |
| Manifest                                | `__MSG_extDescription__`. The `name` stays literal.                                                        |
| Popup HTML                              | `data-i18n` fills text, `data-i18n-<attribute>` fills `placeholder`, `title`, `aria-label`. `localize.ts`. |
| Popup script, content script, feed code | A `Translate` function passed in ([layers.md](layers.md) §Ports).                                          |
| Blur label, "Classifying…"              | JS writes `data-lx-label` / `data-lx-pending`; the stylesheet draws it with `attr()`.                      |
| Peek                                    | `data-lx-peek` carries the post's words, `data-lx-label` the text that follows.                            |

**Chrome localises the manifest and stylesheets, never HTML.** Hence the keys in the popup markup.

**Stylesheet text rides on attributes, not `__MSG_` inside CSS.** Firefox support for it in content-script CSS is unverified. A `<style>` we inject can be refused by the host page's CSP. A custom property set on `<html>` mutates the host ([conventions.md](conventions.md) Invariant 3). `data-lx-*` attributes are already allowed.

**No markup inside a message.** A bold lead-in is its own key next to its body (`tipWordsTitle`, `tipWordsBody`); quotation marks replace italics. That keeps `innerHTML` out of the popup, which AMO lint flags.

**Plurals.** Chrome has none. A count that changes wording gets a one and a many key (`statusTopicsOne`, `statusTopicsMany`). Elsewhere the number is labelled instead of pluralised (`importDone`). A language that needs more forms means extending this.

**Placeholders** are `$NAME$` with a `placeholders` entry, never a bare `$1`. A literal dollar sign is `$$`.

## What stays English

- **The score badge.** A diagnostic readout that bug-report screenshots carry; the popup hint says so.
- **Log output** and **the engine's own error text**, appended to the failure line (`engineFailedWhy`).
- **Names**: FeedLens, X, LinkedIn, Reddit, GitHub. The manifest `name` too.
- **Store listing text.** The dashboards take it per language; it is not in this repo.

## Add a language

1. Copy `public/_locales/en` to `public/_locales/<code>`, with the browser's folder name (`de`, `pt_BR`, `zh_TW`).
2. Translate each `message`. Keep every `$NAME$`. Keep `extDescription` within 132 characters and the `chip*` messages within 18.
3. `npm test`: `src/locales.test.ts` fails on a missing key, a lost placeholder, a stray `$` or an over-long string.
4. Open the popup and a feed with the browser in that language. No test sees wrapping or width.

The step-by-step version for contributors: [development.md](../docs/development.md) §Add a language.
